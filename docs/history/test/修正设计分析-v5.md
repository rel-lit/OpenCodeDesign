# GraphAgent 工作集机制最终理解（v5）

## 1. 核心模型

活跃工作集和临时工作集是**同构的轻量语义条目集合**。

### 1.1 临时工作集（Temporary Working Set）

- **生命周期**：一个 GraphAgent 子代理 session。
- **可见性**：GraphAgent 可以直接访问。
- **初始化**：从活跃工作集复制。
- **容量**：无上限，不淘汰。
- **内容形式**：轻量语义条目（名称 + 类型 + 简要语义）。
- **更新方式**：
  - GraphAgent 请求展开节点 → 邻居加入临时工作集。
  - GraphAgent 请求搜索 DB → 匹配结果加入临时工作集。
  - GraphAgent 请求获取概念详情 → 该概念加入临时工作集。
  - GraphAgent 写入新实体 → 新实体加入临时工作集。

### 1.2 活跃工作集（Active Working Set）

- **生命周期**：长期持久化，跨 session。
- **可见性**：GraphAgent **不能直接访问**。
- **初始化**：无，由系统事件持续累积。
- **容量**：有上限，超过后自动淘汰（LRU 或类似机制）。
- **内容形式**：与临时工作集相同，轻量语义条目。
- **更新方式**：
  - GraphAgent 对临时工作集的任何扩展（展开、搜索、获取、写入），结果同时进入活跃工作集。
  - ChatAgent 或其他系统调用 design 查询/写入时，相关实体也进入活跃工作集。
  - 活跃工作集是“用户长期关注什么”的自动学习结果。

### 1.3 两者的关系

```
活跃工作集（长期 cache）
    ↓ 复制
临时工作集（当前 session 视图）
    ↑ 扩展
GraphAgent
```

GraphAgent 只看到临时工作集。但它的每一次扩展都会同时反馈到活跃工作集，影响未来的 session 初始焦点。

## 2. 轻量语义条目

临时/活跃工作集中的每个条目不是裸 ID，也不是完整实体，而是类似：

```ts
interface WorkingSetEntry {
  id: string           // 内部 ID，用于系统查找
  name: string         // 人类可读的名称
  type: "context" | "node" | "prototype"
  briefSemantics: string // 一句话语义摘要
}
```

例如：
- `{ id: "ctx-xxx", name: "太空探索", type: "context", briefSemantics: "涵盖星际航行、天体探索的核心玩法上下文" }`
- `{ id: "node-yyy", name: "海", type: "node", briefSemantics: "海洋/海域概念" }`

GraphAgent 通过读取临时工作集，可以快速扫一遍当前关注范围内有哪些东西，然后决定深入查看哪个。

## 3. GraphAgent 的工作流程示例

### 3.1 场景：用户说“船”

1. **启动子代理**：临时工作集从活跃工作集复制，包含之前讨论的概念，比如“海”。
2. **GraphAgent 调用 `design_get_temporary_working_set`**：
   - 看到：海、玩家、飞船、星球……
3. **GraphAgent 注意到“海”可能与“船”相关**：
   - 调用 `design_get_concept("海")` 获取详细信息。
4. **系统返回“海”的完整信息，并把“海”加入临时工作集（它可能已经在里面）**。同时“海”也被更新到活跃工作集。
5. **GraphAgent 发现“海”关联很多概念，但没看到“船”**：
   - 调用 `design_expand_node("海")`。
6. **系统把“海”的一跳邻居加入临时工作集**，返回这些邻居的详细信息。
7. **GraphAgent 还是没看到“船”**：
   - 调用 `design_search_graph("船")`。
8. **系统在 DB 中找到“船”节点，把它加入临时工作集和活跃工作集**，返回“船”的详细信息。

### 3.2 连续性

下次用户再聊设计时，新 session 的临时工作集会从活跃工作集初始化。因为“船”和“海”已经在活跃工作集里，所以新 session 一开始就会看到它们，保持讨论连续性。

## 4. GraphAgent 工具集设计

### 4.1 读取工具

| 工具 | 输入 | 输出 | 副作用 |
|---|---|---|---|
| `design_get_temporary_working_set` | 无 | 当前临时工作集中所有轻量语义条目 | 无 |
| `design_get_concept` | `name_or_id` | 概念的完整信息（语义、关系、邻居名称） | 该概念加入临时工作集和活跃工作集 |
| `design_get_context` | `name_or_id` | 上下文及其包含的节点摘要 | 该上下文加入临时工作集和活跃工作集 |
| `design_expand_node` | `name_or_id` | 节点的一跳邻居及其关系 | 邻居加入临时工作集和活跃工作集 |
| `design_search_graph` | `query` | 匹配的节点/上下文/原型摘要 | 匹配结果加入临时工作集和活跃工作集 |
| `design_get_state_summary` | 无 | 图的整体统计 | 无 |
| `design_list_prototypes` | 无 | 所有关系原型 | 无 |

### 4.2 写入工具

| 工具 | 输入 | 输出 | 副作用 |
|---|---|---|---|
| `design_define_context` | `name, semantics` | 新上下文摘要 | 新上下文加入临时工作集和活跃工作集，入 accumulator |
| `design_define_concept` | `name, context, ...` | 新概念摘要 | 新概念加入临时工作集和活跃工作集，入 accumulator |
| `design_refine_concept` | `concept, ...` | 更新摘要 | 入 accumulator |
| `design_withdraw_concept` | `concept, cascade` | 删除摘要 | 入 accumulator |
| `design_relate_concepts` | `from, to, relation, ...` | 关系摘要 | 相关节点加入临时工作集和活跃工作集，入 accumulator |
| `design_withdraw_relation` | `from, to` | 删除摘要 | 入 accumulator |
| `design_define_relation_prototype` | `name, semantics, ...` | 新原型摘要 | 入 accumulator |
| `design_finalize_change` | 无 | 终稿审批 | 提交 accumulator，清空 accumulator |

### 4.3 移除的工具

- `design_workset_get` / `design_workset_add` / `design_workset_remove` / `design_workset_expand`
- `design_get_design`（功能被 `design_get_temporary_working_set` + `design_get_state_summary` 覆盖）
- `design_resolve_reference`（从 GraphAgent 中移除；会写入新节点，不适合作为查询工具）
- `design_get_relations`（功能被 `design_get_concept` 和 `design_expand_node` 覆盖）

## 5. Prompt 设计

### 5.1 用户消息

```text
mode: cognition
request: 请帮我设计“船”这个概念在当前游戏中的作用。

当前活跃工作集摘要（已从长期记忆加载到本次会话）：
- 上下文：太空探索、战斗系统
- 节点：海、玩家、飞船、星球、资源、任务、敌人、武器
- 设计图版本：7

请先读取临时工作集了解当前上下文，然后按需查询和展开相关概念。
```

**注意**：prompt 中不包含临时工作集的具体内容，也不包含完整图状态。只给活跃工作集的摘要作为方向提示。

### 5.2 System Prompt（graph.txt）

需要包含：
1. GraphAgent 身份和职责。
2. 工作集机制说明：
   - 活跃工作集是长期记忆，由系统自动维护，不能被你直接访问。
   - 临时工作集是当前会话的关注范围，从活跃工作集复制而来。
   - 你每次查询、展开、搜索、写入都会自动扩展临时工作集和活跃工作集。
3. 工具列表和用法。
4. 明确说明：图状态不会注入 prompt，你必须通过工具读取。
5. two-stage approval 流程。

## 6. 数据层改动

### 6.1 `TemporaryWorkingSet` 服务

当前：
```ts
export interface TemporaryWorkingSet {
  contextIds: string[]
  nodeIds: string[]
  edgeKeys: string[]
  systemAnalysis: ...
  expandedByGraphAgent: ...
}
```

改为：
```ts
export interface WorkingSetEntry {
  id: string
  name: string
  type: "context" | "node" | "prototype"
  briefSemantics: string
}

export interface TemporaryWorkingSet {
  entries: WorkingSetEntry[]
}
```

- 移除 `capacity`（临时工作集无上限）。
- 移除 `systemAnalysis` / `expandedByGraphAgent`（或移到其他地方）。
- `get` 返回轻量条目列表。
- 新增内部方法 `addEntry(sessionID, entry)`，由工具层调用。

### 6.2 `WorkingSet`（活跃工作集）服务

当前使用 ID 数组：
```ts
{
  activeContextIds: string[]
  activeNodeIds: string[]
  capacity: number
}
```

改为与临时工作集同构：
```ts
{
  entries: WorkingSetEntry[]
  capacity: number
}
```

- 使用 LRU 淘汰。
- 提供 `touch(entry)` 方法，由查询/写入事件调用。
- GraphAgent 不能直接访问。

### 6.3 工具层改动

- 重写 `DesignGetTemporaryWorkingSetTool`。
- 删除 `DesignWorksetAddTool` / `DesignWorksetRemoveTool` / `DesignWorksetExpandTool`。
- 修改 `DesignGetConceptTool`、`DesignGetContextTool` 等查询工具，使其调用 `touchEntry`。
- 新增/修改 `DesignExpandNodeTool`、`DesignSearchGraphTool`。
- 所有写入工具成功后调用 `touchEntry`。

### 6.4 `buildGraphAgentPrompt`

- 移除完整 `graphState` JSON。
- 移除 `temporaryWorkingSet` JSON。
- 只保留 `activeWorkingSet` 的名称摘要。
- 恢复返回字符串。

### 6.5 `task.ts`

- 删除 `system` 参数。
- 恢复通用 task 工具的纯洁性。

## 7. 还需要确认的问题

1. **工作集条目是否包含边？**
   - 边是关系，不是独立概念。是否作为单独条目存入工作集？
   - 还是只在展开节点时返回，不长期保留在工作集中？

2. **`design_expand_node` 展开几层？**
   - 一层邻居？
   - 还是递归多层但只返回一层？

3. **`design_search_graph` 匹配后添加多少结果到工作集？**
   - 全部匹配结果？
   - 还是 top-K？

4. **`design_get_temporary_working_set` 返回格式？**
   - 纯文本列表？
   - 还是 Markdown 表格？

5. **活跃工作集的淘汰策略？**
   - 严格 LRU？
   - 还是上下文/节点分开淘汰？

6. **`design_resolve_reference` 是否完全删除？**
   - 还是保留给 ChatAgent 使用？

## 8. 实施顺序

建议分阶段：

### 阶段 1：止血
- 删除 `task.ts` 的 `system` 参数。
- 恢复 `buildGraphAgentPrompt` 返回字符串。
- 从 prompt 中移除完整 graphState JSON。
- 更新 `graph.txt` 去除 system prompt JSON 说明。

### 阶段 2：重构工作集数据模型
- 把 `TemporaryWorkingSet` 和 `WorkingSet` 改为同构的轻量语义条目集合。
- 实现 LRU 淘汰。

### 阶段 3：重新设计 GraphAgent 工具
- 新增/修改查询工具。
- 删除旧的工作集工具。
- 所有查询/写入工具自动更新工作集。

### 阶段 4：集成验证
- typecheck / build。
- GUI 验证连续性场景。

## 9. 总结

最终理解：
- 活跃工作集和临时工作集是同构的轻量语义条目集合。
- 临时工作集是当前 session 的可访问视图；活跃工作集是长期不可见的记忆。
- GraphAgent 的每次读取/写入都会同时更新两者。
- Prompt 中不注入任何图状态，只给活跃工作集的轻量摘要。
- 工具层负责维护工作集，AI 只负责查询和设计推理。
