# GraphAgent 临时工作集重新理解（v4）

## 1. 新的核心理解

**临时工作集不是 ID 索引集合，而是 DB 和 GraphAgent 之间的中间层 / 视图映射。**

这意味着：
- 临时工作集里应该存储 GraphAgent 需要关注的**完整语义内容**。
- 它是一个**物化视图**或**预构建的关注范围上下文**，而不是裸索引。
- GraphAgent 读取临时工作集时，应该直接拿到人类可读的内容，不需要再自己拼接 ID 或查询数据库。
- 它的作用是**减少 GraphAgent 对底层数据库的关注度**，让 GraphAgent 专注于设计推理。
- 它**仍然不是完整图状态**，只是当前关注范围的视图。

## 2. 之前理解的偏差

| 之前理解 | 正确理解 |
|---|---|
| 临时工作集只存 ID，查询时自动查数据库 | 临时工作集存储已经解析好的语义实体 |
| GraphAgent 需要频繁调用底层查询工具 | GraphAgent 主要读取临时工作集视图，必要时才查全局 |
| 临时工作集需要 AI 手动 add/remove/expand | 临时工作集由系统根据用户请求、活跃工作集、GraphAgent 行为自动维护 |
| 查询工具负责把结果加入临时工作集 | 系统层负责维护临时工作集内容，查询工具只是让 GraphAgent 获取它 |

## 3. 临时工作集应该是什么

### 3.1 内容形态

临时工作集应该是一个**语义化的视图对象**，例如：

```ts
interface TemporaryWorkingSetView {
  contexts: Array<{
    id: string
    name: string
    semantics: string
    nodes: Array<{
      id: string
      name: string
      kind: string
      aliases: string[]
      semantics: string
    }>
  }>
  edges: Array<{
    leftNodeName: string
    rightNodeName: string
    prototypeName: string
    semantics?: string
  }>
  prototypes: Array<{
    id: string
    name: string
    semantics: string
  }>
}
```

**关键**：存的是名称和语义，不是裸 ID。

### 3.2 谁维护它

- **初始化**：子代理 session 启动时，从活跃工作集复制，系统查数据库填充完整语义。
- **自动扩展**：当 GraphAgent 查询全局图（如搜索、展开节点）时，系统把结果自动加入临时工作集并更新视图。
- **写入同步**：当 GraphAgent 调用写入工具创建/更新节点或关系时，系统把新实体加入临时工作集视图。

### 3.3 和活跃工作集的关系

- 活跃工作集 = 长期 cache，存 ID，跨 session。
- 临时工作集 = 当前 session 的语义视图，从活跃工作集初始化，然后根据 GraphAgent 行为自动扩展。
- 活跃工作集是“系统觉得重要的东西”；临时工作集是“GraphAgent 当前正在看的东西”。

## 4. GraphAgent 的工具集应该怎么设计

### 4.1 核心读取工具：获取临时工作集视图

**`design_get_temporary_working_set`**
- 输入：无。
- 输出：当前临时工作集的完整语义视图（上下文、节点、边、原型的人类可读摘要）。
- 作用：让 GraphAgent 一开始就知道自己当前关注的是什么。

这是 GraphAgent 最重要的读取工具。它不应该返回 ID，而应该返回名称和语义。

### 4.2 全局搜索工具

**`design_search_graph`**
- 输入：`query: string`。
- 输出：匹配的名称、类型、简短语义。
- 副作用：系统把匹配结果加入临时工作集并更新视图。

GraphAgent 用它来找自己临时工作集里没有的东西。

### 4.3 展开工具

**`design_expand_node`**
- 输入：`node_name: string`（或 ID，但优先名称）。
- 输出：该节点的邻居、关系、相关上下文。
- 副作用：系统把展开的邻居加入临时工作集视图。

### 4.4 轻量摘要工具

**`design_get_state_summary`**
- 输入：无。
- 输出：整个图的大小统计（多少个上下文、节点、边、原型）。

### 4.5 写入工具

保持不变，但每个写入成功后，系统把新实体自动加入临时工作集视图：
- `design_define_context`
- `design_define_concept`
- `design_refine_concept`
- `design_withdraw_concept`
- `design_relate_concepts`
- `design_withdraw_relation`
- `design_define_relation_prototype`
- `design_finalize_change`

### 4.6 应该移除的工具

- `design_workset_add`
- `design_workset_remove`
- `design_workset_expand`
- `design_workset_get`（被 `design_get_temporary_working_set` 替代）
- `design_get_design`（功能被覆盖）
- `design_resolve_reference`（从 GraphAgent 中移除，或改造为不自动创建节点的纯查询）

## 5. Prompt 中应该包含什么

### 5.1 用户消息（User Message）

- `mode`
- `request`
- `userInput`
- `knownVersion`
- `activeWorkingSet` 的轻量摘要（仅名称，让 GraphAgent 知道用户当前关注什么）
- `changePlan`（refine 模式）
- `force`（refine 模式）

**不包含**完整 graphState JSON。

### 5.2 System Prompt（来自 `graph.txt`）

- GraphAgent 身份和职责。
- 可用工具列表，区分查询和写入。
- **关键说明**：
  - 临时工作集是一个预构建的语义视图，包含你当前需要关注的设计内容。
  - 你首先应该读取 `design_get_temporary_working_set` 了解当前视图。
  - 如果需要查找视图外的东西，使用 `design_search_graph` 或 `design_expand_node`。
  - 写入工具会自动更新临时工作集视图。
- two-stage approval 流程。

## 6. 当前代码需要改什么

### 6.1 数据层：`TemporaryWorkingSet`

当前实现：
```ts
export interface TemporaryWorkingSet {
  contextIds: string[]
  nodeIds: string[]
  edgeKeys: string[]
  systemAnalysis: ...
  expandedByGraphAgent: ...
}
```

需要改为：
- 保留索引字段（用于系统内部维护和同步）。
- 新增**视图字段**或让 `get` 返回视图时自动从索引解析出语义内容。
- 或者直接让 `TemporaryWorkingSet` 同时存索引和视图内容，但 AI 只看到视图内容。

### 6.2 服务层：`Design.getTemporaryWorkingSet`

当前返回的是索引对象。

需要：
- `getTemporaryWorkingSet(sessionID)` 返回索引+视图内容。
- 新增 `resolveTemporaryWorkingSetView(sessionID)` 把索引解析为语义视图。
- 当索引变化时，视图自动重建。

### 6.3 工具层：`tool/design.ts`

需要：
- 修改 `DesignWorksetGetTool` 为 `DesignGetTemporaryWorkingSetTool`，返回语义视图。
- 删除 `DesignWorksetAddTool`、`DesignWorksetRemoveTool`、`DesignWorksetExpandTool`。
- 新增/修改 `DesignSearchGraphTool`：返回语义匹配结果，并调用 `updateTemporaryWorkingSet`。
- 新增/修改 `DesignExpandNodeTool`：按名称解析节点，展开邻居，调用 `updateTemporaryWorkingSet`。
- 所有写入工具成功后，调用 `updateTemporaryWorkingSet` 把新实体加入视图。

### 6.4 Prompt 层：`buildGraphAgentPrompt`

需要：
- 移除完整 `graphState` 注入。
- 移除 `temporaryWorkingSet` 的索引 JSON 注入。
- 只保留 `activeWorkingSet` 名称摘要和 `knownVersion`。
- 不返回 `{ prompt, system }`，恢复为字符串。

### 6.5 通用层：`task.ts`

需要：
- 删除 `system` 参数。
- 恢复通用 task 工具的纯洁性。
