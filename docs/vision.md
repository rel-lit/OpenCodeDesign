# 项目愿景：OpenCodeDesign

## 这个 fork 为什么存在

我想要一个适应我、而不是让我适应它的 AI 设计工具。

我不想学习"怎么用好 AI"。我的思维方式是抽象、碎片化的。我希望 Agent 能把我的自然语言整理成一个稳定的"设计图"，然后以这个图作为我和 AI 之间的共同上下文。

选择 OpenCode 作为基础，是因为我不想自己处理 Build 模式、Plan 模式、API 兼容、基础设施这些专业问题。我只专注在 Design 这一层。

## 我们要做什么

一个以设计图为中心的 AI 助手：

1. **设计图是共同上下文**
   - 图包含：限界上下文（Context）、概念（Concept）、关系（Relation）、关系原型（Relation Prototype）、事件日志。
   - 它表达我的架构意图，不一定符合最佳实践。
   - 它是消除我和 AI 之间指代歧义的单一真相源。

2. **自然语言 → 结构化图**
   - 我在 Design 模式下自然表达。
   - AI 把我的话转成图操作。
   - 有歧义时，AI 让我确认，而不是猜测。
   - 我能在应用前看到 AI 理解的结果。

3. **图可见、可编辑**
   - 我随时能看图，而不只是看 AI 的总结。
   - 我能手动改图，让它符合我的直觉。
   - 图编辑器应该像思维导图，而不是数据库表单。

4. **AI 基于图行动**
   - DesignGraph 子代理维护和分析师。
   - DesignSearch 子代理对比图和项目代码，报告差异。
   - Build/Plan 子代理根据图实现代码。

## 现在不做什么

- 不替代 OpenCode 做成独立产品。
- 不做新的通用聊天界面。
- 不做不经确认就自动修改的 AI。
- 不超出 Windows 桌面端范围。

## 路线图

### Phase 1：侧边栏只读图面板

在 `packages/app` 的 session 界面加一个 Design 图侧边栏。后台新增 API 暴露 `Design.Service.getState()`，前端用列表形式展示 contexts / nodes / edges / prototypes。目标是让我先看见图，不再黑盒操作。

### Phase 2：可视化编辑器

把列表升级成 canvas / SVG 节点图，支持拖拽、双击编辑。写操作走 `VisualEditorProtocol.save(delta)`，直接修改图。

### Phase 3：AI 理解确认

AI 把自然语言转成图操作前，在侧边栏预展示理解结果。让我确认或修改，再写入图。

### Phase 4：AI 基于图行动

DesignSearch 检测代码与图差异；Build/Plan 子代理基于图实现代码变更。

## 指导原则

- 我的直觉是对的，即使不符合常规。
- AI 应该请求澄清，而不是默默猜测。
- 透明优先于自动化。
- 小步、可手动修正的改动，优先于大步、不可逆的改动。
