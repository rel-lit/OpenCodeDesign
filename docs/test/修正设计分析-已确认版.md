# GraphAgent 架构修正最终方案（已确认版）

## 1. 问题根源

### 1.1 三次错误修补

1. **第一轮**：`buildGraphAgentPrompt` 把完整 `graphState` JSON 注入 user message，架空了工作集机制。
2. **第二轮**：把 ID 装饰成 `名称 (id)`，在错误方向上继续修补，prompt 里仍然是内部数据库状态。
3. **第三轮**：给通用 `task` 工具加 `system` 参数，把 JSON 图状态塞进 system prompt，用胶水代码掩盖架构问题，严重破坏 `task` 通用性。

## 2. 工作集模型

### 2.1 活跃工作集（Active Working Set）

- **生命周期**：长期持久化，跨 session。
- **可见性**：GraphAgent **不能直接访问**。
- **内容形式**：轻量语义条目（`id + name + type + briefSemantics`）。
- **容量**：有上限，超过后自动 LRU 淘汰。
- **更新方式**：
  - GraphAgent 对临时工作集的扩展（展开、搜索、写入），结果同时进入活跃工作集。
  - ChatAgent 或其他系统调用 design 查询/写入时，相关实体也进入活跃工作集。
  - `getNode`、`getContext`、`findNodesByName`、搜索结果、写入成功等事件都应触发激活。

### 2.2 临时工作集（Temporary Working Set）

- **生命周期**：一个 GraphAgent 子代理 session。
- **可见性**：GraphAgent 可以直接访问。
- **初始化**：从活跃工作集复制。
- **内容形式**：与活跃工作集同构的轻量语义条目。
- **容量**：无上限，不淘汰。
- **更新方式**：
  - `design_expand_node` → 邻居加入临时工作集。
  - `design_search_graph` → 匹配结果加入临时工作集。
  - 写入新实体 → 新实体加入临时工作集。
  - **注意**：`design_get_concept` 等纯查询工具不修改临时工作集，严格读写分离。

### 2.3 两者的关系

```
活跃工作集（长期记忆，GraphAgent 不可见）
    ↓ 复制
临时工作集（当前 session 视图，GraphAgent 可见）
    ↑ 扩展
GraphAgent
```

### 2.4 轻量语义条目

```ts
interface WorkingSetEntry {
  id: string
  name: string
  type: "context" | "node"
  briefSemantics: string
}
```

**注意**：工作集只包含 context 和 node，不包含边和 prototype。prototype 固定且随边一起提供。

## 3. GraphAgent 工具集

### 3.1 查询工具（只读）

| 工具 | 输入 | 输出 | 副作用 |
|---|---|---|---|
| `design_get_temporary_working_set` | 无 | 临时工作集中所有条目的自然语言摘要 | 无 |
| `design_get_concept` | `name_or_id` | 概念详情（含语义、相邻边数组） | 无 |
| `design_get_context` | `name_or_id` | 上下文及其节点摘要 | 无 |
| `design_expand_node` | `name_or_id` | 节点的一跳邻居及边语义 | 邻居加入临时/活跃工作集 |
| `design_search_graph` | `query` | 按名称/别名匹配的节点/上下文摘要 | 匹配结果加入临时/活跃工作集 |
| `design_get_state_summary` | 无 | 图的整体统计 | 无 |
| `design_list_prototypes` | 无 | 所有关系原型 | 无 |

### 3.2 写入工具（只写 accumulator）

| 工具 | 输入 | 输出 | 副作用 |
|---|---|---|---|
| `design_define_context` | `name, semantics` | 新上下文摘要 | 加入临时/活跃工作集，入 accumulator |
| `design_define_concept` | `name, context, ...` | 新概念摘要 | 加入临时/活跃工作集，入 accumulator |
| `design_refine_concept` | `concept, ...` | 更新摘要 | 入 accumulator |
| `design_withdraw_concept` | `concept, cascade` | 删除摘要 | 入 accumulator |
| `design_relate_concepts` | `from, to, relation, ...` | 关系摘要 | 相关节点加入临时/活跃工作集，入 accumulator |
| `design_withdraw_relation` | `from, to` | 删除摘要 | 入 accumulator |
| `design_define_relation_prototype` | `name, semantics, ...` | 新原型摘要 | 入 accumulator |
| `design_finalize_change` | 无 | 终稿审批 | 提交 accumulator，清空 accumulator |

### 3.3 移除的工具

从 GraphAgent 工具集中移除：
- `design_workset_get` / `design_workset_add` / `design_workset_remove` / `design_workset_expand`
- `design_get_design`
- `design_resolve_reference`（会写入新节点，不适合作为查询工具；可保留给 ChatAgent 或完全删除）
- `design_get_relations`（功能被 `design_get_concept` 和 `design_expand_node` 覆盖）

## 4. 输出格式规范

### 4.1 节点详情输出

- 保留节点自身 ID。
- 节点内部引用的其他 ID 替换为语义名称。
- 示例：
  ```
  概念：船（node-xyz）
  所属上下文：太空探索
  语义：水上/太空载具
  别名：船舶、飞船
  关系：
    - 船 --[属于]--> 交通工具
    - 海 --[关联]--> 船
  ```

### 4.2 `design_expand_node` 输出

- 只返回被扩展节点与其一跳邻居之间的边。
- 不返回邻居与其他节点之间的边。
- 使用语义名称，不返回内部 ID（节点自身 ID 除外）。
- 边中包含关系原型的名称和语义。

### 4.3 `design_get_temporary_working_set` 输出

自然语言形式，示例：
```
当前临时工作集：
- 上下文 "太空探索"：涵盖星际航行、天体探索的核心玩法上下文
- 概念 "海"：海洋/海域概念
- 概念 "船"：水上交通工具
```

工作集内部仍存储 `id`，但对外展示时隐藏 ID。

## 5. Prompt 设计

### 5.1 用户消息（User Message）

```text
mode: cognition
request: 请帮我设计“船”这个概念在当前游戏中的作用。

当前活跃工作集摘要（已从长期记忆加载到本次会话）：
- 上下文：太空探索、战斗系统
- 概念：海、玩家、飞船、星球、资源、任务、敌人、武器
- 设计图版本：7

请先读取临时工作集了解当前上下文，然后按需查询和展开相关概念。
```

### 5.2 Refine 模式

Refine 阶段在同一子代理 session 内进行，不需要跨 session 传递状态。

Refine 阶段的用户消息用文字描述已批准的方向和授权范围：

```text
mode: refine
request: 用户已批准以下变更方向：在太空探索上下文下创建"船"概念，并与"海"建立关联。你已被授权自主合理化细节，请开始细化并调用写入工具累积变更。
```

或未授权时：

```text
mode: refine
request: 用户已批准以下变更方向：在太空探索上下文下创建"船"概念，并与"海"建立关联。请通过 Question 面板逐个细节询问用户，确认后再写入。
```

### 5.3 System Prompt（`graph.txt`）

需要包含：
1. GraphAgent 身份和职责。
2. 工作集机制说明：
   - 活跃工作集是长期记忆，系统自动维护，GraphAgent 不可直接访问。
   - 临时工作集是当前 session 的语义视图，从活跃工作集复制而来。
   - `design_expand_node`、`design_search_graph`、写入工具会自动扩展临时工作集和活跃工作集。
   - `design_get_concept`、`design_get_context` 等查询工具只返回信息，不修改工作集。
3. **明确声明**：图状态不会注入 prompt，必须通过工具读取。
4. 可用工具列表，明确区分查询工具和写入工具。
5. two-stage approval 流程（judge → refine → finalize）。

## 6. 数据层改动

### 6.1 `TemporaryWorkingSet` 服务

当前：
```ts
export interface TemporaryWorkingSet {
  contextIds: string[]
  nodeIds: string[]
  edgeKeys: string[]
  systemAnalysis: ...
  expandedByGraphAgent: ...
}
```

改为：
```ts
export interface WorkingSetEntry {
  id: string
  name: string
  type: "context" | "node"
  briefSemantics: string
}

export interface TemporaryWorkingSet {
  entries: WorkingSetEntry[]
}
```

- 移除 `capacity`。
- 移除或弱化 `systemAnalysis` / `expandedByGraphAgent`。
- `get` 返回轻量条目列表。
- 新增内部方法 `addEntry(sessionID, entry)`，由工具层调用，不对 AI 暴露。

### 6.2 `WorkingSet`（活跃工作集）服务

当前使用 ID 数组：
```ts
{
  activeContextIds: string[]
  activeNodeIds: string[]
  capacity: number
}
```

改为与临时工作集同构：
```ts
{
  entries: WorkingSetEntry[]
  capacity: number
}
```

- context 和 node 分开淘汰。
- context 只有当所有以其为 context 的 node 都被淘汰后，才被淘汰。
- 提供 `touch(entry)` 方法，由查询/写入事件调用。
- GraphAgent 不能直接访问。

### 6.3 工具层改动

- 重写 `DesignGetTemporaryWorkingSetTool`。
- 删除 `DesignWorksetAddTool` / `DesignWorksetRemoveTool` / `DesignWorksetExpandTool`。
- 新增/修改 `DesignExpandNodeTool`、`DesignSearchGraphTool`。
- 修改 `DesignGetConceptTool`、`DesignGetContextTool` 输出格式，用名称替换内部引用 ID。
- 所有写入工具成功后调用 `touchEntry`。

### 6.4 `buildGraphAgentPrompt`

- 移除完整 `graphState` JSON。
- 移除 `temporaryWorkingSet` JSON。
- 只保留 `activeWorkingSet` 的名称摘要。
- 恢复返回字符串。
- Refine 模式下用文字描述已批准方向和授权范围。

### 6.5 `task.ts`

- 删除 `system` 参数。
- 恢复通用 task 工具的纯洁性。

## 7. 与 OpenCode 上游架构的对照

- 上游没有 design/GraphAgent 子系统；当前 design 子系统是自有实现。
- 上游 `task` 工具没有 `system` 参数，只是子代理启动器。
- 上游 `PromptInput.system` 是 session/LLM 编排层保留字段，没有工具从参数注入。
- 上游 agent 通过 `prompt` 字段承载系统提示词，通过 instruction 系统注入额外上下文。
- 上游子代理对话框原样显示 `prompt` 内容，所以正确做法是让 prompt 本身人类可读。
